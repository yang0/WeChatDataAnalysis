# Node.js rewrite validation

Task: https://github.com/yang0/magpie-gptfree/issues/20

- JavaScript implementation: SQLCipher 4.x raw/base keys, strict page HMAC, AES-CBC without padding, streaming page output, WAL checksum/commit index, SQLite quick_check, source stability, isolated publication and cancellation.
- Fixed real encrypted SQLite/WAL vectors were generated by the prior independent Python implementation. Tests query the decrypted Chinese messages using an actual SQLite engine. No Python is run by the product or its tests.
- Node test suites cover correct output, latest committed WAL data, key/HMAC/WAL/SQLite corruption, path/symlink isolation, source mutation, cancellation, actual worker threads, GUI API permissions, key redaction and native capture coordination.
- CI matrix: Windows and Ubuntu, Node 22 and current Bun; browser sandbox/form/decrypt/responsive tests; Windows native DLL build and Python-import rejection, real/fake C ABI probes.
- Native helper source revision and DLL hash are stored in native/manifest.json. The package includes only the built DLL and PowerShell bridge, not Python wheels or a Python environment.
- Local Chromium cannot start in this executor due to a process-singleton socket restriction; browser validation is performed by CI. CI results are linked from the tracking issue after final SHA verification.
- Real WeChat key acquisition and real Magpie installation still require user-machine validation.

`main` and compatibility branch `magpie-plugin` carry the plugin. Original complete application remains on `original-app` at `fffe9ca2bdb27f786227cff9d3620940ad8c034c`.
